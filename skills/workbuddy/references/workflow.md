# 从一句话到成片：七道闸门

这条流程存在的唯一理由：**返工几乎都发生在"没定就往下走"的地方**。每道闸门都是一次便宜的纠错——比渲完 450 帧再看片便宜两个数量级。

```
P0 立项 → 1 定风格与卡 → 2 分镜表 → 3 打样 → 4 施工 → 5 声音 → 6 质检 → 7 交付
```

---

## P0 立项：先答七个问题

没答完不要 `wb create`。

1. **给谁看**（客户 / 平台观众 / 内部评审）——决定信息密度与字体大小。
2. **一句话目标**：看完要记住什么？这句话最后会变成结尾那屏的字。
3. **时长与画幅**：几秒、竖屏还是横屏。规格一旦定了就别中途改（改规格 = 全部重排）。
4. **发布平台**：有没有字幕安全区、有没有声音默认静音（静音平台要把信息放在画面上）。
5. **素材从哪来**：客户给了什么、要从网站收什么（`wb assets gather`）、哪些必须程序生成。
6. **风格与镜头卡**：这一支用什么整片风格、关键镜头用哪几张卡。
7. **验收标准**：谁签字、看哪几帧、什么算过。

答完写成两行放进 `--prompt`，它会进 `BRIEF.md`，后面每道闸门都对着它检查。

## 1 定风格与卡（不要只定一个）

```bash
wb style list
wb style read --slug 09-bauhaus          # 判据 / 引擎契约 / 效果配方 / 色板
wb style frames --slug 09-bauhaus        # 8 张参考帧，逐张看
wb card search 纸张
wb card show --card 纸张展开 --style paper-unfold
```

- **整片风格**（`--style`）决定色板、字体、节奏、引擎——是"这个片子长什么样"。
- **镜头卡**（`--cards`）决定某一段怎么动——是"这一镜怎么做"。
- 两者可以同时用：风格给底，卡给动作。**只用其中一个通常不够**：只有风格会显得每镜都一个模子，只有卡会显得片子没有整体语言。
- 看过参考帧再决定"像不像"。看不懂配方就先别开工，去 `wb style source --slug …` 读上游实现。

## 2 分镜表：六列，一行一镜

```bash
wb create --dir D --spec 1080x1920@30 --style 09-bauhaus --duration 12
wb spec scaffold --dir D --rows 3      # 生成表骨架，然后手写
```

| 镜头 | 帧区间 | 镜头卡 | 这一镜要做什么 | 屏幕上出现什么 | 文案 / 声音 |
| --- | --- | --- | --- | --- | --- |
| shot-1 | 0–90 | 纸张展开 · paper-unfold | 从空白纸建立"规则" | 米色纸纹铺满，四条装订孔先落位 | （纸声） |
| shot-2 | 90–210 | — | 数字从 0 弹到 30,000 | 计数器 + 逐格推进的刻度 | "三十年" |
| shot-3 | 210–360 | — | 收在结论上 | 大字两行，背景压暗 | "你的一生，只有三万天" |

规矩：

- **帧区间加起来必须等于总时长**（`wb create` 会警告，`wb spec validate` 会报错）。
- 一行只写一个意图；写了两件事就拆一镜。
- "文案 / 声音"列写的是**最终会被念出来/看到的字**，不是"讲一下背景"。
- 分镜表是给人看的合同，`timeline.json` 才是给程序读的排期；两者不一致时以 `timeline.json` 为准，但要把表改回来。

## 3 打样：最便宜的一步，最不该省

```bash
wb preview --dir D --at 0,4.5        # 先看两帧定调
wb render --dir D --range 0,90 --wait   # 3 秒样片
```

- **3–6 秒**：一个完整动作 + 一次转场，足够暴露节奏、字号、色彩问题。
- 样片和整片分开产（`.out/pilot.mp4` / `.out/film.mp4`），样片**不做响度归一**，别拿去当交付。
- 样片给用户看之前先自己看一遍拼图；配色、字号、留白不对就先改，别浪费一次评审。
- 用户确认样片后再渲整片。**没确认就渲整片是返工第一大原因。**

## 4 施工

- 一段一个文件，**≤120 行**；共享部件拆成 `shot-N-parts.tsx`。
- 改共享部件时在文件顶部递增 `// rev N`，并说明改了什么（下一个 Agent 靠它判断要不要重新看样片）。
- 颜色只从 `theme.ts` 取；需要风格固定色（包豪斯的红黄蓝）就在场景顶部写常量，不要散落在十几处。
- 时间轴单一真相：所有时长用 `useVideoConfig().durationInFrames` 推，**不要写 `const DUR = 120`**。
- 抖动/噪声用 `scene-kit/det.ts`，不用 `Math.random()`。
- `wb preview` 一镜一镜看，别攒到最后一起看。

## 5 声音

顺序不能反：**旁白 → 音乐 → 音效 → 对拍**。

```bash
wb voice plan --dir D            # 只估算，看排期合不合理
wb voice say  --dir D            # 真合成 + 按真实时长重排
wb sfx search "paper whoosh"     # 短词
wb audio add --dir D --file sfx/paper-whoosh.mp3 --role sfx --at 1.2
wb audio add --dir D --file bgm.mp3 --role bgm --at 0 --fade-in 1 --fade-out 1.5
wb sync bind --dir D --music cue-5
wb verify --dir D
```

- 旁白先于音乐：镜头时长要跟着句子走，音乐跟着镜头走。
- 音效对齐动作帧（翻页、盖章、落位），别按"感觉"往前挪 3 帧。
- BGM 铺底 −16 ~ −22dB；旁白区间引擎会自动压 −12dB，不用手写。
- 超过 8 个 cue 先离线混成一条 `mix.wav` 再上轴（`timeline.audio.cues` 太多会让渲染变慢）。
- 交付前量一次：底噪 ≥ −26dB 静音段、整体 −16 LUFS、峰值 −1.5 dBTP。

## 6 质检

```bash
wb qa --dir D                 # 整片
wb qa --dir D --file .out/pilot.mp4   # 样片（帧数必然对不上，忽略那条）
```

机器能查：帧数、黑场、静止过久、单帧闪烁、空白帧、安全区、色带、斜边过渡、字体、响度。
机器不能查：**好不好看**。所以还要：

1. 看拼图（构图、字号、留白、层级）；
2. 用 `--crop` 看 1:1 局部（锯齿、色带、文字描边）；
3. 对着参考帧比（`wb style frames`）——对不上的项，要么改，要么在 `STYLE.md` 写一行「偏离：X 改为 Y，因为 Z」。

## 7 交付

```bash
wb render --dir D             # 整片
wb qa --dir D
wb export --dir D --subtitles --draft
```

交付物：成片 mp4、`timeline.json`、`scene-*.tsx`、`STYLE.md`、`storyboard.md`、`BRIEF.md`、剪映素材包（客户要再剪时给）。字幕优先用工程里的 `timeline.subtitles`（`wb voice say` 已写好），`wb export` 会自动出 SRT。

## 返工原因（按出现频率排）

| 现象 | 真正的原因 | 下次怎么防 |
| --- | --- | --- |
| 渲完发现节奏不对 | 没打样就整片 | 闸门 3 不可跳 |
| 字幕和画面对不上 | 先加了音乐再改旁白 | 闸门 5 的顺序 |
| 字体变了、字宽全变 | 用了没注册的字体族 | 只用 `theme.ts` 的族，或写偏离行 |
| 中间几秒很空 | 分镜表那一行只有一个"氛围"意图 | 一行一个可验收的动作 |
| 风格"像又不像" | 引擎被简化（three 用 div 摆） | 读 `STYLE.md` 的引擎契约，跑 `wb render` 前两道闸 |
| 同一帧两次渲出来不一样 | 用了 `Math.random()` / 帧序状态 | `scene-kit/det.ts` + 闭式解 |
| 交付后客户说太吵 | 音效叠了三层 | 一镜一个主音效，其余压到 −18dB 以下 |
| 越改越慢 | 场景文件超 120 行、共享部件没有版本号 | 拆文件 + `// rev N` |
