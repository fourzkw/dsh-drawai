## 2. Right-sidebar tab API (two-stage registration)

**Stage 1 — the type.** `dsh-client-ui-sidebar-right/lib/types/client/tab-registry.d.ts:153`:

```ts
register(definition: SidebarRightTabDefinition): () => void;
```

`SidebarRightTabDefinition` (same file, :68-109) = `{ id: string; kind: string; patterns?:
readonly string[]; priority?: 'extension'|'builtin'|'fallback'; canOpen?: (address: string) =>
boolean; title: (address: string) => string; guide?: readonly SidebarRightGuideEntry[] }`.
`priority` defaults to `'extension'`. `SidebarRightGuideEntry = { order: number; title: () =>
string; description?: () => string; icon?: ComponentType<IconProps> }`. A second registration of an
`id` throws; one kind holds at most one `builtin` + one `extension`.

**Stage 2 — the body/title.** `ctx.slots.register({ name: 'sidebar.right.pane.tab', key:
definition.id }, Body)` and `{ name: 'sidebar.right.pane.tab.title', key: definition.id }`, both
wrapped in `ctx.slots.inject(<key>, () => ...)`. Live shape from
`dsh-client-ui-sidebar-documentpreview/lib/client.js:1361`:

```js
ctx.effect(() => ctx.slots.inject("sidebar.right.tab.document", () => ctx.slots.register(
  { name: "sidebar.right.tab.document", key: PLAIN_BODY_ID }, TextBody)));
```

The component reads props via the framework-injected hook `useTabInfo()`
(`contract/slots.d.ts:117-139`):

```ts
SidebarRightTabInfo = {
  sidebar: { expanded: boolean; fullscreen: boolean };
  panel:   { id: PaneId };
  tab: TabRecord & { visible: boolean; navigation: { address; params; revision }; signal:
        AbortSignal; actions: SidebarRightTabActions };
}
```

`SidebarRightTabActions = { openResource(address, options?), openTab<K>(kind, options?), close() }`
— always aimed at the session the tab is in.

**Programmatic opening** (`service.d.ts:105-168`, `ISidebarRight` = `ctx.sidebarRight`):

```ts
openResource(address: string, options?: SidebarRightOpenResourceOptions): void;
openTab<K extends string>(kind: K, options?: SidebarRightOpenTabOptions<K>): void;
close(tabId: TabId): void;  active(): TabRecord | undefined;
isExpanded(): boolean;  toggleExpanded(): void;
focus(tabId): void;  split(paneId?): PaneId | undefined;
float(tabId, rect?): void;  dock(paneId): void;
```

`SidebarRightPlacement = { paneId?: PaneId; replaceTab?: TabId; revealIfOpened?: boolean }`;
`openResource` adds `kind?` + `params?`, `openTab` adds `params?`. Both **expand the column in the
same step** ("content the user cannot see is not opened"); an address outside `dsh-resource://`, one
no type claims, or an unregistered `kind` **throws** ("a wiring mistake, not a user error"). Is a
tab visible/active? State lives per session in the dockkit layout store —
`stores.d.ts`: `SurfaceState { layout: LayoutState; history: History; minted: number }`,
`SidebarRightState { bySession: Record<string, SurfaceState> }`. The sole docked `guide` tab can
never close (`canCloseTab`).

**Agent-opened programmatically? No host-side path exists.** Grepping every `.js`/`.d.ts` in the
checkout, `openResource(`/`openTab(` appear only in browser halves: `ui-chat/lib/client.js:8322-8323`
(file links), `ui-sidebar-files/lib/client.js:451`, `ui-sidebar-right/lib/client.js:181,3697`. No
tool, remote, or host service exposes it. The agent's only route is §6.

## 3. Client plugin package shape

`dsh-client-ui-sidebar-right/package.json` (mirrored by `dsh-client-ui-sidebar-files`,
`-documentpreview`): `"type": "module"`, and

```json
"exports": { ".": {...}, "./client": { "types": "./lib/types/client/index.d.ts",
  "default": "./lib/client.js" }, "./src/*": "./src/*" },
"dsh": { "client": { "inject": ["@deepseek-ai/dsh-api-session-controller", "...",
  "@deepseek-ai/dsh-client-ui-session"], "platform": "web" } },
"files": ["lib/index.js", "lib/client.js", "lib/types/**/*.d.ts"],
"scripts": { "bundle": "tsdown", "watch": "tsdown --watch" }
```

`dsh.client` marks the client half; `platform: "web"`; `inject` lists package dependency edges;
optional `external: string[]` (non-baseline module requests — only
`dsh-api-session-controller` and `dsh-api-workspace-controller` use it) and `immediately: boolean`
(used by `dsh-client-hmr`). `exports["./client"] → lib/client.js` **is** the client entry; the bundle
resolves as `<id>/client` or the bare id via `stripClientSuffix`
(`dsh-client-modules/lib/types/client/manifest.d.ts:138`).

Authors write **TypeScript/TSX compiled ahead of time** by tsdown into `lib/client.js`. The host
serves built artifacts: "The host serves built client bundles, so `pnpm run build` must have produced
each `lib/client.js` before launch; a missing bundle fails activation loudly"
(`dsh-client-modules/README.md`). `dsh-client-modules` scans enabled Loader entries for `dsh.client`,
composes `window.__DSH_BOOT__` (`WebBootEntry { id, url, rev, inject?, immediately?, external? }`),
and serves combo URLs under `/plugins/??…&rev=…`. Bundle format:

```js
window.__ModuleLoader__.load({ id: "@deepseek-ai/dsh-client-ui-sidebar-right",
  factory: (require) => { ... } })
```

Lazy-CJS: executing a bundle only registers the factory; all side effects (CSS injection included)
run at materialization. The browser half exports `inject: string[]` + `apply(ctx)`
(`dsh-client-ui-layout/lib/types/client/index.d.ts:106,113`).

## 4. Component model

**React 18** (`react ^18.2.0`, `react-dom ^18.2.0`, `@types/react ~18.3.1`) — bundles
`require("react")` and `require("react/jsx-runtime")`. Business plugins are plain React components
that "receive session and workspace data through typed props and never wire subscriptions
themselves" (`dsh-client-ui-renderer/README.md`).

Prop contract from `@deepseek-ai/dsh-client-ui-slots`: `PropsRuntime<'slot'>`, `InjectFace<F>`,
`PropsLocale<'ns'>`, `PropsRenderSlots<'a'|'b'>`, `PropsStore<Store>`, plus `SlotHookFactory`,
`SnapshotSelectorHook`, `HostObservable`, `BoundActions`, `SlotRenderer`. Real example
(`dsh-client-ui-cordis/lib/types/client/CordisPanel.d.ts:5-7`):

```ts
export type CordisPanelProps = PropsRuntime<'sidebar.footer.action'>
  & InjectFace<CordisPanelFace> & PropsLocale<'cordis'>;
export declare function CordisPanel({ wide, useSessions, useInventory, ..., t }: CordisPanelProps):
  import("react").JSX.Element | null;
```

**Styling**: CSS Modules (`src/client/**/*.module.css`) inlined by tsdown into the bundle and
injected at materialization as `style[data-plugin="<pkg>"][data-plugin-css="<pkg>/<file>.module.css"]`
(`dsh-client-ui-sidebar-right/lib/client.js:36-43`). CSS class names are hashed (`geFEbW_guide`).
Dynamic packages instead use the `styles.insert(css)` closure symbol.

**i18n**: `ctx.locale.register(ns, { zh, en })` then `ctx.locale.bind(ns)` or the slot-injected `t`
seat; namespaces are typed by augmenting
`declare module '@deepseek-ai/dsh-client-ui-slots' { interface LocaleNamespaceMap { sidebarRight:
SidebarRightKey } }` (`dsh-client-ui-sidebar-right/lib/types/client/contract/slots.d.ts:7-11`);
`zh` is the key-set source of truth (`locales.d.ts`), `en` is checked against it; `verify-client-ui-i18n`
enforces that all client copy enters through dictionaries. Language packs use
`ctx.locale.addLanguage({ id, label, fallback })` + per-locale `register(ns, lang, dict)`.

## 6. Dynamic / agent-authored UI

Two packages, different jobs. `dsh-client-ui-cordis` is the **human-facing** surface: its
`CordisPanel` is the frame-wide inventory/approval panel in the `sidebar.footer.action` seat, plus
`cordis_define` / `cordis_run` cards. There is **no `CordisPanel` API for authoring a panel** — for
that, the agent uses `dsh-tool-cordis` + `dsh-cordis-host-runner` + `dsh-cordis-client-runner`.

Yes, the agent can define a client panel at runtime. `cordis_define` records a package with a
browser half; `cordis_run` activates it, returning `awaiting-approval` until a person approves
(`CordisPanelFace.onApprove(requestId, approveFutureVersions)` / `onDecline(requestId)`). The browser
half (`evaluator.d.ts:66`, `runtime.d.ts:46-59`) is "an async function body returning a plugin",
evaluated by `new Function(...parameters, ...)` with this fixed symbol surface:

```
parameters = ["React","console","styles","host","harness",
              ...Object.keys(traps), "process","Buffer"]
traps = { setTimeout, setInterval, clearTimeout, clearInterval, fetch, require }
```

`harness` is a trap (host-half only). Plain JS only: "no JSX, no TypeScript, no module imports…
build elements with `React.createElement`". The returned plugin's `apply(ctx)` receives a
whitelisting proxy (`guard.d.ts:51`): `ctx.get(name)`, `CTX_VERBS`, and any service declared in the
plugin's own `inject` — undeclared access throws
`service "X" is not declared by your plugin. Declare it on the plugin you return: { inject: ['X', …], apply(ctx) { … } }`.
`slots` and `theme` are specially guarded; `slots` registration yields to the calling package's fiber.

**What it can define:** any of the 61 slot keys — the catalog's own `example` field is the template:

```js
return { inject: ['slots'], apply(ctx) {
  ctx.slots.inject('conversation.chat.assistant-actions', () => ctx.slots.register(
    { name: 'conversation.chat.assistant-actions', id: 'my-entry', order: 100, label: 'My entry' },
    () => React.createElement('div', null, 'hello'))) } }
```

So a real right-sidebar tab type is reachable by declaring
`inject: ['slots','sidebarRightTabs','sidebarRight']` and running the two stages of §2.
`GUARDED_SLOT_KEYS` forces `key:'self'` for `tool.view.cordis`, the seat meant for a package's own
business view inside its `cordis_run` card. Per-deployment slot admission does not exist: "Slot
admission has no carrier — the dispatched row declares services, not target slots."

**Constraints**: definitions are session-scoped and process-local (cleared on `cordis_stop`,
`cordis_undefine` or DSH restart); a reloaded page holds nothing until run again; the sandbox "is not
a security boundary — treat a dynamic package like bash access"; no timers/network (route through
`host.call(method, args)` to a host-half `harness.handle`); later registrations receive a lower
shadowing priority; render-time crashes are reported `{ slot, message, stack, abdicated }` via
`reportRenderFailure` and surface through `cordis_inspect_self`, not the run receipt.

## 7. Hot reload

`@deepseek-ai/dsh-client-hmr` (dev-only, `dsh.client: { inject: [], platform: "web", immediately: true }`).
Node half stat-polls every graph bundle from `ClientModuleRegistry.artifactBaseline(id)`
(`pollIntervalMs` default `500`); a changed bundle enters `rebuilt(id)` (only content changes reach
the graph) and is broadcast as `graph`/`rebuilt` frames over SSE at `/plugins/events`. Browser half:
`invalidate(id, rev)` selects the plugin's revisioned one-resource combo URL, `prefetch(id)` loads
and registers the new factory while the old fiber still serves, then registry-first teardown, drain
the old fiber's unload, `delete entry.fiber`, remove owned `<style data-plugin>` tags, `entry.refresh()`
re-import and remount, `fiber.await()` rethrow.

**Needed for live dev:** the plugin must be a composed Loader entry with a built `lib/client.js`, and
a rebuild watcher must be running against the same host — `pnpm run dev:web` "or any tsdown watch
process that writes the plugin's `lib/client.js`". Without a watcher the chain stays idle. Plugins
depending on the reloaded one reload with it; React state in the reloaded plugin is lost (data layer
survives); there is no rollback (a failed reload leaves the entry FAILED and visible).
