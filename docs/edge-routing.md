# 连线路由

路由在编辑事务中完成，渲染、命中、标签定位和导出读取同一份结果。
新建工作流节点连接默认使用圆角正交线和手动模式，已有连线和手动折点不自动改写。
AI 应先按阅读方向分层、统一对齐和间距，读取节点坐标后自行规划各条线的中间折点，检查节点、文字和线路是否遮挡。
指定直线、直角、曲线或手动折点仍可按用户意图使用。

| 模式 | 判据 | points 归属 |
| --- | --- | --- |
| 直线 | edgeStyle=none | 用户 |
| 自动避障 | libavoidRouting=1 | 引擎生成，可保存 |
| 手动正交 | drawaiRoutingMode=manual，或旧文件有折点 | 用户 |
| 普通正交 | drawaiRoutingMode=orthogonal，或旧文件无折点 | 简单连接，不绕其他节点 |

固定连接点仍使用 exitX/exitY、entryX/entryY；其优先级不受模式切换影响。
拖动线段或单独平移整条线后切入手动模式。右键“恢复自动排线”清除手动折点、
保留固定连接点；“关闭自动避障”切到普通正交。AI 使用 avoid:true/false，
clearPoints 可单独清折点。曲线切换保留可编辑路径，归入手动模式。

AI 手动布线使用 addEdge / setEdge 的 points:[{x,y},...] 参数：
按源端到目标端顺序填写中间折点，不含端点，使用绝对画布坐标，保留小数，最多 1000 点。
显式指定后切入手动模式；points:[] 清空折点并保持手动，省略则保留原路径。
不可同时指定 avoid:true；只有用户明确要求自动避障时才使用 setStyle{avoid:true,clearPoints:true}。
正交模式会补齐端点段；仅在用户明确要求非正交逐段连线时使用 line:"straight"。
建议先确定节点布局，再以 layout:"none" 写入精确路径。

### 端点与折点

连接到节点的起终点由 `exit`、`entry` 和节点位置确定；插件会补上端点和引出段。
`points` 只填写确实需要的中间转折，不要重复写起点、终点或相同折点。两侧沿进出方向对齐且通道畅通时，可显式使用 `points:[]`。

例如：A 的位置与尺寸为 `(60, 60, 240, 140)`，B 为 `(400, 40, 480, 270)`。
A 的右侧连接点为 `(300, 130)`，B 的左侧连接点为 `(400, 175)`。可用：

```js
{ op: 'addEdge', from: 'A', to: 'B', exit: 'e', entry: 'w', line: 'rounded', points: [{ x: 340, y: 175 }] }
```

不要再把 `(400, 175)` 放进 `points`：插件生成的目标引出段与重复端点可能使路径折返。连线后读回坐标和折点，并在图像通道可用时查看画布实际渲染；发现折返或遮挡时用 `setEdge` 调整并复查。没有预览时不要声称已经完成视觉检查。

## 引擎与事务

- src/routing/router.js：前后端共用的文档适配、路线校验和增量失效。
- src/routing/node-runtime.js：宿主私有 VM 内延迟初始化引擎。
- tools/build.mjs：相同引擎与适配器内联进客户端私有作用域；不依赖 CDN、WASM 或动态求值。
- 上游固定版本及许可见 src/routing/NOTICE.md 和 vendor/。

求解使用 draw.io 的 AvoidRouting + libavoid。安全间距从 16 开始，失败时按
8、4、2 重试；平行线理想间距为 14。每次接受路线前校验坐标、正交性、穿节点和折返。
生成折点不再强制吸附到 5 的网格；用户拖动仍使用现有网格吸附。

节点增删、移动、缩放或显隐变化会检查连接线以及旧/新障碍附近的自动线，
并把共享端点的相邻自动线纳入同批求解。远处路线保持原样。
合法的内部路线随整体选区平移；碰到外部障碍则重新求解。
共同容器不作为实心障碍，内部兄弟节点仍参与避障。隐藏节点不参与，锁定可见节点参与。

节点拖动沿用现有合并撤销事务，路线在提交前更新，因此一次撤销恢复节点和路线。
新建/改接连线的预览使用同一引擎，最后一次合法预览通过临时字段交给提交端验证并接收，
临时字段在提交前移除；相同输入的预览使用有界缓存。

无法满足的约束标为 drawaiRouteStatus=blocked，界面和宿主摘要提示无可用通道，
不把穿模路线当作成功。手动折点若进入节点内部，不会被悄悄推走。
自环保留独立的环形绘制规则。引擎当前在主线程同步求解；超大密集画布的 Worker 化
不在本次改动内。标签排版继续沿用现有渲染逻辑，本次不引入标签与路线的循环求解。

## 验证

node tools/check-routing.mjs 覆盖真实引擎、增量失效、预览提交与格式往返。
node tools/check-route-preview.mjs 覆盖连接点、手动线段和旧路径几何回归。
宿主检查需要 DSH SDK；无 SDK 的开发环境可以显式使用仓库现有测试适配器：

    node --loader ./tools/audio-test-sdk-loader.mjs tools/check-host.mjs

该适配器检查工具参数边界，不能代替真实 DSH SDK 的 schema 验证。
