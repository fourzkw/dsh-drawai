# 登录流程 · 纯文本画法（横杠 + 竖杠）

同一张流程图，**只用键盘上的字符**画：`+ - |` 纯 ASCII 一版，`┌ ─ │ ┐` Unicode 制表符一版。
内容与 `README.md` 那一组一致：`开始 → 输入账号 → 校验 →（通过）进入首页 /（失败）回到输入账号`。

## 一、纯 ASCII（`+ - |`，任何字体都不会跑版）

```text
        +----------+
        |   开始   |
        +----+-----+
             |
             v
        +----------+
        | 输入账号 |<-----------+
        +----+-----+            |
             |                  |
             v                  |
        +----------+            |
        |   校验   |            |
        +----+-----+            |
             |                  |
       通过  |                  | 失败
             v                  |
        +----------+            |
        | 进入首页 |            |
        +----------+            |
             |                  |
             +------------------+
```

> ASCII 版最诚实的写法是**竖排回环**（从底部绕回右侧）。横着折回"输入账号"左侧当然也能画，
> 但那条横线要跨过 5 行 13 列的数字对齐，字体一变就散架 —— 见下面「三、别踩的坑」。

## 二、Unicode 制表符（`┌ ─ │ ┐`，观感最像真图）

```text
        ┌──────────┐
        │   开始   │
        └────┬─────┘
             │
             ▼
        ┌──────────┐
        │ 输入账号 │◄───────────┐
        └────┬─────┘            │
             │                  │
             ▼                  │
        ┌──────────┐            │
        │   校验   │            │
        └────┬─────┘            │
             │                  │
       通过  │                  │ 失败
             ▼                  │
        ┌──────────┐            │
        │ 进入首页 │            │
        └──────────┘            │
             │                  │
             └──────────────────┘
```

注：`◄`（U+25C4）在个别等宽字体里是**半角**还是**全角**并不统一，最保险就退回 ASCII 版的 `<`。
下面这版把箭头全部换成纯 ASCII，制表符保留：

```text
        ┌──────────┐
        │   开始   │
        └────┬─────┘
             │
             v
        ┌──────────┐
        │ 输入账号 │<───────────┐
        └────┬─────┘            │
             │                  │
             v                  │
        ┌──────────┐            │
        │   校验   │            │
        └────┬─────┘            │
             │                  │
       通过  │                  │ 失败
             v                  │
        ┌──────────┐            │
        │ 进入首页 │            │
        └──────────┘            │
             │                  │
             └──────────────────┘
```

## 三、别踩的坑（这一档的真实代价）

| 坑 | 说明 |
|---|---|
| **中文是 2 列宽** | 一个汉字占两个等宽字符位。`+----------+` 是 12 列，装 5 个汉字（10 列）刚好；写成 4 个汉字就得多补两格。算错一格整张图就歪 |
| **字体决定生死** | 必须等宽字体（Consolas / 更纱黑体 / Sarasa Mono）。落到比例字体里，上面的对齐全部作废 |
| **中文标点更毒** | 全角 `（）`、`：`、`，` 都是 2 列，且部分字体里居中显示，看起来"多半个空格" |
| **箭头是赌博** | `▼ ◄ ─` 属制表符/几何图形块，不同字体宽度可能 1 或 2 列；`+  -  \|  >  v  ^` 才是绝对安全的 |
| **改动要手工重排** | 加一个节点 = 手工挪整张图；`校验` 改成 `校验密码` 时那个框要加宽，右边所有竖线跟着右移 |
| **没有语义** | 它就是一坨字，Markdown 不认、工具不解析，纯靠人眼读 |

## 四、对齐怎么算（要自己加框时用）

节点框宽度固定 **12 列**：`│ ` + 8 列内容 + ` │`。
8 列内容 = 4 个汉字 / 8 个半角字符。

```
┌──────────┐     ← 12 列
│ 输入账号 │     ← 2 + 8 + 2 = 12 列
└──────────┘
```

5 个汉字挤不进 8 列，就得把整张图的框加宽到 14 列（`│ ` + 10 列 + ` │`），并同步右移所有竖线。
