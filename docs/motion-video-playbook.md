# 动效视频 · 制作流程与规范

这份文档规定**一支片子从"想做"到"能播"要经过哪几道闸门、每道闸门的产出长什么样、谁来点头**。
`docs/motion-video.md` 讲的是工具怎么调；这份讲的是**活怎么干**。

三条铁律，写在最前面：

1. **内容未定，不动手。** 立项没确认就写代码，等于用 600 帧去猜用户想要什么。
2. **一镜未过，不量产。** 先做 1 个镜头给用户看，认可后再铺其余镜头。
3. **用了镜头卡，就必须读 demo 源码。** 凭卡名和配方文字重写，等于放弃卡里所有调校（见 §3）。

---

## 1. 阶段与闸门

| 阶段 | 干什么 | 产出 | 闸门（谁点头） |
| --- | --- | --- | --- |
| **P0 立项** | 问清 7 件事，写成一句话 brief | `BRIEF.md` | 用户确认内容与硬约束 |
| **P1 方向** | 出 2–3 个**风格方向**，每个配一句参考 + 镜头语汇 | 方向卡（正文里给，不落盘） | 用户选一个 |
| **P2 分镜** | 把方向拆成逐镜表：每镜像什么、说什么、响什么 | `storyboard.md` + 画布上的镜头卡连线 | 用户认可分镜表 |
| **P3 资产** | 界面纹理 / 截图 / 字体 / 色板 / 音效清单 | `assets/`、`theme.ts` | 自查（见 §4） |
| **P4 打样** | **只做第 1 镜**，出真视频（不是静帧拼图） | `.out/film.mp4`（单镜） | **用户明确"方向对了"** |
| **P5 量产** | 其余镜头逐镜移植，一镜一验 | 全部 `scene-*.tsx` | 每镜自验 + 全片预览 |
| **P6 声音** | 按分镜的"响什么"列做声音设计 | `assets/sfx/mix.wav`、音轨 | 自查响度（§5） |
| **P7 质检交付** | 全片帧检 + 回填画布 + 文档同步 | clip 进节点、`storyboard.md` 更新 | 用户验收 |

**闸门不过不许进下一阶段。** 尤其 P4 —— 打样被否，改的是这一镜；量产被否，改的是整片。

---

## 2. P0 立项：必须问清的 7 件事

一次问完，不要边做边问。缺哪一项就先按默认值填，并在 brief 里标「假设」。

| # | 问题 | 为什么先问 | 默认值（用户没意见时） |
| --- | --- | --- | --- |
| 1 | **给谁看、在哪播**（发布页 / 产品内 / 朋友圈 / 投屏） | 决定时长、字号、安全区、要不要字幕 | 产品发布页 |
| 2 | **一句话内容**：这条片子只让人记住哪一句 | 决定文案与分镜重心 | 由用户原话提炼，回读确认 |
| 3 | **时长 × 画幅 × 帧率** | 决定分镜数量与镜头卡的时间表 | 16:9 · 1920×1080 · 30fps · 20s |
| 4 | **要不要声音？要哪一类**（只有音效 / 音效+底噪 / 音乐 / 配音） | 声音最晚在分镜前定，否则时长与节奏全要重排 | 音效 + 极低底噪，无音乐无配音 |
| 5 | **素材边界**：能不能用真实截图 / 品牌色 / 字体 / 真人 | 决定走"截真图"还是"手搭 HTML" | 允许自建 HTML 界面 mock |
| 6 | **硬约束**：必须出现的文案 / 必须避开的说法 / 版权要求 | 免返工 | 无 |
| 7 | **验收标准**：什么样算过 | 免"感觉不对"式扯皮 | 用户能说出"哪一镜哪一处不对" |

> 第 4 条是这次踩过的坑：声音被当成收尾环节，结果片子定稿后才发现要么无声、要么节奏要重排。**声音是立项项，不是收尾项。**

## 3. P1 方向 & 镜头卡规范

### 3.1 方向卡长什么样

给 2–3 个，每个不超过 6 行：**一句话概念 / 参考质感 / 运镜语汇 / 适合什么内容 / 不适合什么**。
不要给"风格 A / 风格 B"这种空词，要给可执行的画面。

### 3.2 用镜头卡的硬规定

`lib/motion/shotcraft/upstream/SKILL.md:145-151` 已经写明，这里复述成流程：

1. `shotcraft_search` 搜到卡后，**必须再用 `cardId + styleKey` 搜一次**，拿到配方与 demo 源码路径。
2. **读 `upstream/demos/**/<Card>.tsx` 全文**，不要只读注释里的时间表。
3. 移植，不是重写。要继承的东西：时间表（帧号）、缓动曲线、透视与相机参数、光与影的层（谁画在谁上面）、材质与 grain、错峰量。
4. 只允许替换：**内容**（文字 / 图 / 数据）、**配色**（走 theme token）、**品牌元素**。
5. 如果确实要偏离 demo，在 `storyboard.md` 里写一行「偏离：X 改为 Y，因为 Z」。
6. **每张卡都必须 `addEdge` 连到视频节点**。连线顺序 = 镜头顺序，卡时长 = 段长，连上的卡还会冻结进 `assets/` 当参考。画布上有断连的卡时 `motion_project create` 会直接报错——不要用"只作参考"来绕过，那等于参考、顺序、段长三样一起丢。

> 判定标准：用户看完成片，能指着镜头说「这就是那张卡」。做不到就是没移植成功。

### 3.2b 用整片风格的硬规定（引擎保真）

风格包里的 `engines` 是上游真用的引擎，不是形容词。移植时必须真跑同一套：

1. `mg_style {action:"read", slug}` 先看 `engines / engineFiles / engineNote`；`{action:"source", files:[…]}` 读该引擎的上游实现正文（shader、renderer、后处理）。
2. three.js 风格（03 / 10 / 22）：在 `<canvas>` 里用 `three` 或 `@remotion/three` 建 WebGLRenderer + 场景/相机，按 `useCurrentFrame()` 驱动 `renderAt`，后处理用 `three/addons`。
3. WebGL2 风格（07 / 09 / 12 / 20）：`getContext("webgl2")` + 上游 GLSL 原样编译，逐帧传 uniform；该风格同时要 Canvas2D 层的（09 分色版、20 索引帧）两层都要在。
4. Canvas2D / DOM 风格按 `engines` 来（DOM 风格如 04 用多层 `backdrop-filter` 景深，不是画布贴图）。
5. **禁止用更省事的方式替代**：CSS 3D、`transform: perspective` 摆 div、纯 Canvas2D 渐变/模糊冒充实 3D 或 shader、静态图位移——静帧像、一动就露。
6. `motion_render start` 会扫工程源码（不含 `.out` / `node_modules`）：重引擎 `three / webgl2 / webgl` 缺失直接拒绝渲染。确实要换实现，先在 `STYLE.md` 写一行「偏离：引擎 X 改为 Y，因为 Z」，渲染带 warning 通过，偏离会记进任务返回。
7. **动效也要看真片**：`mg_style {action:"frames", slug}` 从上游 demo 按 `cues.json` 的时间点抽 8 张参考帧（缺字体/纸纹会用占位兜底并在 `notes` 里写明）。写场景前先 `read_image` 逐张看，再按 `STYLE.md` 的「效果配方」逐项做：转场是 wipe 还是切、落地有没有 impact/地面环、相机有没有漂移/推/甩/抖、motion blur 几采样、颗粒是逐像素还是几百个点、有没有蒸汽/拍翼这类二次运动。规范只验"形"不验"动"，不看帧就会做成"形似而动不像"。

> 判定标准：把成片和上游 demo 并排放，**运动质感要能对上**（透视、光照、流体/印刷颗粒、后处理辉光），不是"颜色差不多"。

### 3.3 一张卡对应一句"为什么选它"

分镜表里每镜都要有一句：**这一镜解决什么叙事任务**。卡是手段，不是目的；
「因为好看」不是理由，「因为要在 2 秒内证明它是立体的」才是。

## 4. P2 分镜表规范

`storyboard.md` 必须能独立读懂，不依赖对话记录。每镜 6 列：

| 镜头 | 帧区间 | 镜头卡 | 这一镜要做什么（叙事任务） | 屏幕上出现什么（可验收） | 文案 / 声音 |
| --- | --- | --- | --- | --- | --- |

要求：

- **帧区间写死**，且与 `timeline.json` 完全一致；改时长必须同步改两边。
- "屏幕上出现什么"必须是**看得见的名词**（"卡从插槽里拔起，原位留补丁"），不能写"很有质感"。
- 声音列在 P2 就要填（哪怕只写"纸响 / 落锤"），P6 只做实现，不重新设计。
- 画布上的镜头卡节点与连线顺序 = 时间轴顺序，改顺序要同时改画布。

### 4.1 分镜表写在画布上（推荐，可复刻）

`storyboard.md` 是编译产物；**真相来源可以在画布上**，这样别人拿到这张 `.drawai` 就能接着做。做法是"现有节点 + 极小标记 + 严格格式"，不新增节点类型、不改画布 schema：

| 画布元素 | 标记 | 格式 |
| --- | --- | --- |
| 文本节点 | `【分镜表】`（label 首行） | 六列表格，同 §4 的列；**时长必须写 `172f`**，镜号连号，各幕之和 = 视频节点时长 |
| 文本节点 | `【风格】` | `page/text/muted/accent/border: #RRGGBB`，`serif/sans/mono: 字体名`，`materials: 瓷白 / 香槟金` |
| 文本节点 | `【旁白】` | `## shot-N` 一节、一句一行（`motion_voice` 原生认这套） |
| 图片 / 音频节点 | `【素材】` + 第二行用途 | 被拍主体 / 界面纹理 / BGM / 旁白；音频标明用途 |
| 图片节点 | `【目标帧】545f` | 第几帧应该长这样；交付时逐张比对 |
| 边 | 卡 → 视频的连线 label | `第1幕`（把卡钉到某一镜，别再靠顺序猜） |

三条解析规则，破了就解析不了：表头六列不能缺；时长只认 `172f` 这种写法（写 `5.7` 秒直接报错）；镜号必须连号。

用 `motion_spec {action:"scaffold"}` 拿三块模板节点的 `diagram_apply` ops，`{action:"validate"}` 逐条报缺（`error` 必修、`warn` 建议），`motion_project create` 在没有显式 storyboard 时直接读画布上的【分镜表】并按表里的帧数排时间轴。

**一张【分镜表】，不是一镜一个节点。** 每一镜是表里的一行；把八镜写成八个文本节点，画布上就不再是一张表，`motion_project` 也读不到分镜（`motion_spec {action:"validate"}` 会直接报"拆成了 N 条"）。分镜表节点宽 700、放在视频节点左侧一列。

原则一句话：**节点是真相来源，spec 是编译产物**。画布上写得清，换个人（或换一次对话）也能复刻出来。

## 5. P4 打样：这一关最重要

- **只做第 1 镜**，做到接近最终质量，渲染成**真视频**发给用户（不要只发静帧拼图——拼图会把 1920 缩到 650 宽，细线全糊，双方都会误判）。
- 打样时同步说明：这一镜用了哪张卡、继承了哪些参数、哪里做了品牌替换。
- 用户回一句「方向对了」= 通关；回「差距太大」= 回去读 demo 源码，不要靠调参数硬凑。
- 打样通过后再量产，**其余镜头按同一套参数骨架**，避免四镜气质漂移。

## 6. 技术规范（写代码时）

| 项 | 规定 | 原因 |
| --- | --- | --- |
| 时间轴单一真相 | 时长一律读 `useVideoConfig().durationInFrames`，不写死 `DUR` 常量 | 旁白/重排会改总长 |
| 共享组件改动 | 改 `components/**` 后必须递增对应 `scene-*.tsx` 顶栏的 `// rev N` | `bundleKey` 只 hash scene 源码，不递增会读到旧 bundle（表现为输出字节完全不变） |
| 颜色与字体 | 只从 `theme.ts` 取，不手写十六进制 | 换主题要一处生效 |
| 文件体量 | 单场景 ≤120 行，公共原语抽到 `components/` | 可读、可 diff |
| 界面素材 | 真实界面走 `motion_assets {action:"gather", url, brand}`（首页+内页一次收：favicon/og 图/主视觉/内联字标/多页聚合配色字体/2 倍视口截图，另补 Simple Icons、Clearbit、高清 favicon 三条 logo 兜底）；只要一块就 `page` 截、再 `crop` | 手搭 div 拼界面 = 永远差一口气；collect 的实测色比调色调得像 |
| 品牌字标 | 官方 SVG 直链用 `motion_assets {action:"fetch", url}`，别截图别重画；拿不到官方素材就上"纯文字占位"问用户 | 形近字体冒充一眼假 |
| 判细节 | 拼图用来看**构图与节奏**；看**细节与曝光**必须 `read_image` 单帧或采样像素 | 缩图会骗人 |
| 渲染 | `motion_render start` 立即返回，**不要睡眠轮询**；中间干别的，需要时 `status` | 646 帧约 5–6 分钟，progress 严重滞后 |

## 7. P6 声音规范

**要不要声音在 P0 定**；一旦要，按下面做：

1. **先出 cue 表**（写进 `storyboard.md` 的声音段）：`时间(秒) — 声音 — 对应画面动作 — 音量`。一行一个点，先审表再做。
2. **素材**：`motion_sfx search` 用**短词**（"whoosh" 有、"paper whoosh transition" 没有），`get` 可一次下多条。
3. **混音**：超过 ~8 个 cue 就不要一条条 `motion_audio add`，用脚本离线混成**一条** `assets/sfx/mix.wav` 再挂一条轨：
   - 48kHz 立体声，长度 = 片长（末尾留 0.6–0.7s 淡出，避免切在波峰上）；
   - 每条 cue 有 fade-in / fade-out（默认 4ms / 50ms），否则会有"啪"的爆音；
   - 母带 `tanh` 软限幅，峰值 ≤0.9。
4. **底噪**：留一条极低（约 −26dB）的 drone 或 room tone 铺满全片，把静默段缝起来——**无声的空档比有声的空档更露怯**。
5. **响度**：交付目标 **−16 LUFS / 真峰 −1.5 dBTP**（渲染时归一化），交付前用 `motion_qa` 复核。

## 8. P7 质检与交付

`motion_qa {action:"inspect"}` 必须满足：

- [ ] 帧数与时间轴一致
- [ ] 无纯黑段、无单帧闪烁、无连续空白帧
- [ ] 静止段 <2.4s（设计停留要能在分镜表里解释）
- [ ] 四边安全区 warn 可接受（全出血画面必然 warn，但要逐条看过）
- [ ] 有声音时必须 `audio-level` pass 且真峰达标

交付动作：

1. `motion_render apply` 回填画布视频节点（覆盖同一个 clip）。
2. 更新 `storyboard.md`（帧区间、文案、声音段）与 `BRIEF.md`。
3. 提交时给用户：**一段话说清这版改了什么** + 一张 6–9 帧拼图 + 需要他决定的问题（不要只说"做好了"）。

## 9. 常见返工原因 → 预防动作

| 症状 | 真因 | 预防 |
| --- | --- | --- |
| "和镜头卡差距太大" | 只读配方文字，凭理解重写 | §3.2 读 demo 源码再移植 |
| "风格不对" | 没有 P1 方向闸门 | 先给 2–3 个方向让用户挑 |
| "声音怪 / 没有声" | 声音当收尾项 | P0 就定；P2 就写 cue 表 |
| "两镜之间很跳" | 只做了镜内节奏，没设计镜间缝合 | 分镜表里写清镜间转场（收灯/开灯/切/推） |
| 改了半天没变化 | 改了共享组件但没递增 rev | §6 表格第二行 |
| "白上白，看不清结构" | 光/材质对比不足，只在缩图上判断 | 看单帧；给底板与层之间留明度差 |

## 10. 给用户的一页 brief（可直接复制）

```
1. 给谁看 / 在哪播：
2. 只让人记住哪一句：
3. 时长 / 画幅 / 帧率：
4. 要不要声音（音效 / 音效+底噪 / 音乐 / 配音）：
5. 能不能用真实截图、品牌色、指定字体：
6. 必须出现 / 必须避开的说法：
7. 什么样算过：
```
