# 原生画布格式与兼容迁移

新建画布默认保存为 `名称.drawai`，内容是带 `format: "dsh-drawai"`、`schemaVersion: 1`、项目 ID 和多页文档的 JSON。媒体位于 `名称.drawai.media/`；旧格式仍使用 `名称.media/`。分享时可用原有画布包导出/导入功能打包主文件与媒体。

## 文档和命令边界

`src/document-core.js` 是前后端共享的文档层，负责空文档、归一化、深拷贝和事务。现有用户操作通过 `applyLocal` 使用共享事务；`src/document-commands.js` 统一分发命令，AI 的现有 ops 在事务草稿上执行，失败时不提交草稿。已有操作语言与渲染器保持兼容；本阶段没有新增生成节点或工作流执行器。

事务隔离文档修改，不撤回已经发生的媒体 IO 或远端调用。文件保存继续使用宿主文件服务、工作区范围检查、写入协调器与内容指纹乐观锁。撤销快照包含嵌套的节点扩展数据，不与当前文档共享可变对象。

原生文档沿用现有形状、样式、页面、图层、节点、标签、连线和叠放顺序模型。节点和连线可以保存额外 JSON 字段，供后续创作功能使用；drawio 的 `data` 属性仍遵循既有字符串属性规则。生成任务和 UI 偏好仍使用原有存储位置，密钥不进入文档。

## 自动迁移

界面首次打开 `.drawio` 时，请求宿主自动迁移到同目录的 `.drawai`。宿主在检查工作区范围后串行执行：解析全部页面，保留页面/单元身份与顺序，复制媒体到独立目录，校验源文件未改变，再通过宿主文件服务提交新文档。界面随后绑定新路径。

原 `.drawio` 和原媒体目录保留。完整原 XML 存放在原生文件的 `compat.drawio` 字段中，包括未识别的单元、包装属性和页面设置；这些内容保留不代表渲染器新增了对它们的支持。兼容导出把已编辑的页面应用到原 XML 模板，继续保留未知内容。

再次打开原路径时，根据来源路径与源指纹复用已迁移文档。已有的同名非迁移文档不会被覆盖；源文件迁移后被外部编辑时，报告冲突，由用户处理两个版本。AI 工具遇到已迁移的旧路径时也会解析到新文件。

运行中、排队中或等待交付的绘制任务，以及进行中的视频导出，会推迟迁移，当前仍打开旧画布。任务结束后关闭并重新打开画布即可迁移。已加载的历史绘制/导出记录随后更新到新路径。迁移不在用户正在编辑时通过轮询触发。

媒体先在同目录临时目录完成复制，再重命名发布；拒绝媒体目录中的符号链接和不属于本次迁移的已有目标。复制或提交失败可能留下临时目录或带来源标记的媒体副本，重试不会覆盖原稿。文档与媒体属于两个文件系统对象，本阶段不提供跨进程的多文件原子事务。

## 兼容与验证

- `.drawai` 和 `.drawio` 都可以打开、保存和作为工具操作目标；不填扩展名默认 `.drawai`。
- “另存为”保留来源文档的多页结构；指定 `.drawio` 可导出已有绘图内容。创作扩展 JSON 字段不属于 drawio 格式，不能通过 drawio 往返保留。
- 原生版本号不受支持时拒绝打开，避免较旧插件覆盖新格式。
- `node tools/check-native-canvas.mjs` 覆盖多页迁移、未知 XML、参数扩展、事务回滚、媒体隔离、重复迁移、冲突与画布包往返。
- `node tools/check-host.mjs` 覆盖路由自动迁移、原生读写、AI 操作、乐观锁及兼容另存为；`npm test` 运行完整现有回归。
