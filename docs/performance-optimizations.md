# 第一批优化：计算内核与应用内绘制队列

交付日期：2026-10-18（北京时间）。这一批在 P0 基础上优化绘制计算，并提供图片/视频共用的应用内队列。

## 已实现

- k-means 在质心完全不变时结束迭代；空簇导致精确周期重复时跳过完整周期，并执行最后一次迭代，保持原来的质心、标签、误差及种子选择结果。
- 超采样颜色完全相同时复用上一计算结果，保留原有浮点值及距离相等时的选择顺序。
- 众数滤波与局部对比检查共用一次邻域遍历，减少重复读标签。
- 图片解码与完整分析进入共享 Worker 池，保留原有参考档位分析和逐块绘制数据；宿主主线程可继续处理请求。
- 图片和视频入口可连续加入队列，默认一个任务运行，视频任务内部仍最多 4 帧并行。等待项支持上下移动、暂停、取消；失败/取消后可按原参数重试，后续任务继续。
- 视频运行时可暂停；先收完在途帧，再暂停抽帧。暂停后其它画布可使用计算槽位，恢复后从下一帧继续。暂停期间维护原媒体令牌的心跳。
- 队列暂停只停止派发后续任务，当前任务继续完成。图片的运行中取消会等待当前 Worker 计算结束，再丢弃结果；界面显示“正在取消”。
- 任务绑定会话、画布、页面、来源和提交参数。重复点击相同未完成任务会合并；任务列表按当前会话筛选。
- 结果等待原画布接收，不占计算槽位；同页后续任务等待接收和保存确认，其它页面可以继续。每个结果通过原有撤销/保存通道加入，带有可写回 drawio 的任务标记，收到保存确认后才显示完成。
- 保存失败或发生重载时保留结果。已持久化的标记用于确认结果，缺失时恢复待应用结果；原节点已删除、替换或锁定时保留结果并显示可复制错误，可重试加入或放弃结果。
- 常规视频进度通知合并到约每秒 4 次；完成、取消和错误及时更新。

打开图片/视频的绘制选项，选择参数后点击“加入绘制队列”。右下角可查看本会话各画布的任务。队列最多保留 16 个未完成任务，素材编码内容有 64MiB 的估算预算，已结束历史保留少量记录并可清除。

切换标签页、页面或对话可保留任务。主动关闭画布会取消该画布的未完成任务。本批队列保存在应用内存中；刷新、插件卸载和宿主重启会中断。跨重启的任务列表、宿主后台执行、持久化检查点、批量多选提交及完整资源预算仍待后续阶段实现。

视频采样仍使用既有浏览器路径，FFmpeg 顺序解码、原始像素传输、二进制上传和硬件编码尚未切换。视频导出已另行迁移为宿主后台渲染与编码，保留帧率、白底和音频行为。

## 视频复用策略调整

近似整帧复用已移除，界面不增加相关开关。浏览器不再生成用于近似判定的低分辨率灰度指纹。

- 精确复用限定在当前任务相邻帧：上传 PNG 的 SHA-256 与规范化绘制参数全部相同，才等待并复用前一帧的有效结果。参数包括输出尺寸、碎片档位、画风、颜色数、去背景和字符预算；命中前仍校验参数。相同像素的不同 PNG 编码会保守地重新计算。
- 复用帧仍按原帧号写入媒体包，保持帧数、时长和音频时间位置。只保留上一帧的结果依赖，不在内存中累积全部 SVG。
- 不同画面重新计算轮廓。若候选调色板适用，可省去颜色聚类：检查对象是经过缩放、透明合成及背景处理后的全部前景工作像素。任一颜色的最近候选色亮度误差超过 8，或任一 RGB 通道误差超过 12，就重新生成调色板；小面积亮色与近似等亮度的新颜色都能触发。
- 调色板以实际生成帧为基准，约每 2 秒刷新一次，间隔限制为 1～120 帧；精确重复帧可持续复用。接受旧调色板的帧不重置刷新计数，并行计算完成的旧共享结果也不会覆盖后来生成的新调色板。
- 缓存依赖按提交顺序预留，兼容分块文件读取完成顺序与内联上传不同的情况。失败会拒绝后续依赖并唤醒等待提交的请求，取消和访问权限沿用原有任务边界。

适配阈值是复用策略的内部保守边界，绘制内核原有量化、碎片和预算规则仍生效。该检查针对工作分辨率，不恢复采样阶段已经丢失的细节。现有视频需重新绘制后才能获得更新结果。

`check-video-reuse.mjs` 通过真实媒体路由与 Worker 验证暗背景小亮角色、角色移动、缓慢变亮、等亮度换色、精确重复、参数切换、周期刷新、分块/内联并行、前序失败传播及任务归属。该检查已接入 `npm test`。

## 同机交替对照

为避免将不同日期的 CPU 电源/温度状态误当成收益，使用同一进程、相同输入，预热后交替运行 P0 快照和优化版，每版测量 3 次并比较中位数。每次显式 GC 在计时前执行；每次输出均核对完整结果摘要。

| 固定场景 | P0 计算中位数 | 优化后 | 耗时减少 |
|---|---:|---:|---:|
| 静止 480p 单帧 | 586ms | 350ms | 40.4% |
| 缓慢运动 1080p 单帧 | 3287ms | 1495ms | 54.5% |
| 复杂彩色 480p 单帧 | 819ms | 748ms | 8.8% |
| 透明 480p 单帧 | 857ms | 455ms | 46.9% |
| 图片校准夹具 | 2507ms | 2176ms | 13.2% |
| 小图片校准夹具 | 470ms | 364ms | 22.5% |

环境为本机 Ryzen 9 8945HX、Windows x64、Node 22.19.0。视频参数为 medium / default / 6 色，使用 PNG 解码后的像素；图片保持完整分析和绘制步骤。这是顺序计算内核的局部结果，不包含浏览器 seek、Worker 传输、网络、结果应用或视频导出，不能解释为整段视频同等提速。

原始数据位于 `.drawai-cache/trace-comparisons/2026-10-17T16-39-45-122Z/summary.json`（目录时间为 UTC）。可保存待比较的旧版模块后运行：

```powershell
node --expose-gc tools/compare-trace-performance.mjs --baseline _local/trace-image-before-p1.mjs
```

P0 基准工具仍可运行，用于观察 Worker 并行及整段宿主局部耗时。曾测得首次优化版本在部分跨日期样本中更慢，因此不使用跨日期数字宣称收益；上表采用最终算法的交替对照结果。

## 暗部配额与大图自动保存

默认按暗部和亮部的粗 RGB 色桶有效丰富度分配总色位，并以较弱的面积权重避免细小噪点占走大量颜色。纯黑等单色区域只需要一个色位，深蓝、深棕等不同暗部颜色获得更多区分空间。总颜色数保持用户选择的值；显式传入 `colorsDark` 或正数 `colorsFill` 时继续尊重指定配额，`colorsDark:0` 保留全图统一量化行为。图片与视频使用同一策略，已有复刻需要重新绘制才会应用。

画布内嵌原图和 SVG 后容易超过旧的 4MiB 请求上限。画布写回使用 128MiB 上限，原图绘制使用 96MiB 上限，渲染回执保留 32MiB，上述之外的控制请求仍为 4MiB。原图完整保留。绘制结果自动加入画布并触发保存，不要求点击保存确认；队列收到宿主成功回执后自动继续。同页保存请求串行发送，后续编辑使用最新回执中的版本，保存期间的轮询不会覆盖本地工作副本。失败时保留结果并显示具体错误，提供重试自动保存入口。

`check-host.mjs` 验证超过 4MiB 的真实画布写回及原图完整性；`check-image-trace.mjs` 验证大于 4MiB 的有效 PNG 绘制；`check-auto-save.mjs` 用延迟传输验证连续保存、版本衔接、无需确认的回执和失败重试。

## 宿主后台视频导出

MP4 / WebM / GIF 导出请求发起后，宿主 Worker 按帧序号读取 SVG，使用 resvg 转为白底 PNG，由 FFmpeg 编码，并自动保存到画布旁。移除了导出所需的浏览器 `Image`、Canvas、PNG 编码和 base64 帧上传；网页定时器只刷新任务卡片，冻结或刷新网页不会影响后台任务。原视频直接在宿主转换。文件以独立任务 ID 命名，任务临时目录在结束时清理；已保存结果不会因关闭页面、下载失败或移除任务记录被删除。

`hostSvgRender` 单独记录 Worker 渲染耗时，`renderedFrames` 记录渲染帧数；宿主成功保存时即完成性能报告，后续可选的浏览器下载不再计入任务完成耗时。任务列表按会话和画布隔离，最多并行 4 项，完成/失败历史有界保留。宿主或插件退出仍会停止未完成任务；本批不提供跨宿主重启续跑。

`check-video-export.mjs` 使用实际 Worker 和 FFmpeg，在没有网页逐帧调用及 finish 请求的情况下验证独立完成、帧数和时间戳、原尺寸、镂空白底、音频、GIF 循环、结果持久保存、失败记录、取消和目录清理。`check-video-audio.mjs` 验证客户端只提交后台任务，不创建导出画布，视图卸载仅停止轮询、重新挂载恢复任务，以及可选下载失败不影响宿主结果。
